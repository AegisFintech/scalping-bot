## Daily accounting and honest proof

`demo_scorecards` reads one repeatable-read, read-only, bounded seven-Singapore-date
snapshot for the configured demo account/XAUUSD/current programme. It uses immutable
broker close deals, including partial closes at their actual broker time. Signed
commission/swap/conversion fees are already included, never deducted twice.
Deposits are not trade profit. External cashflows, broker open marks, actual model
spending, account return and equity drawdown are explicitly null in this view.
The existing UTC risk accounting remains separate.

First/current partial dates do not count as complete positive/negative/flat days.
Unresolved scoped broker events withhold those day classifications. Missing scope,
future/unordered clocks, over5,000 deals, DB timeout or unavailable observations
withhold the scorecard rather than select a profitable subset. Same-time deal
changes are aggregated; realized-ledger drawdown is a lower bound, not equity risk.

The unprivileged one-minute witness has no database/provider/broker credentials.
It GETs only bounded fresh controller evidence, retains immutable completed-allocation
facts/reviews (including zero-fill/negative/unknown results), and verifies actual
registered successors. Distinct profile hashes matter; repeated baseline IDs do not
create different strategies. Freshly re-read source evidence establishes the latest
26-allocation-window milestone; archival files alone cannot manufacture it. A
separate protected root restart receipt must bind to an actually filled completed
allocation. A recorded restart can therefore precede its completed-allocation proof.
The observer has no order, restart, cancellation or promotion authority.

Storage is preflighted (512 files/4MiB and2GiB free reserve); no automatic eviction
or overwritten completed report. Missing/stale/failing observer data stays unavailable.
A latest-window proof is not whole-harness completion or economic qualification.
The existing /learning adds these views; the landscape layout remains unchanged.

The latest26 trial census reads existing qualified SQL terminal-proof functions:
proven zero-fill groups, proven unsent groups, proven closed groups and the
remaining open/unproven groups stay distinct. Proposals, provider claims, WAIT,
failed and REQUESTING contexts retain their trial/profile/source attribution.
No proposal-minus-fill inference is used. Completion receipts retain proposal/claim
denominators and the frozen failure/unknown review; nonfills absent from the
frozen controller contract are explicitly null there, separate from the fresh
DB census. Root ownership is tested independently of the runner UID.
