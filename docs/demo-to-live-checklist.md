# Demo to Live Checklist

Completing this checklist indicates readiness for a separate human review. It does not enable live trading.

This release cannot submit live orders because production composition uses
`DisabledLiveGateway` and leaves live startup checks false. A future
live-readiness review must first approve and test a separate broker-capable
wiring change; the checklist below then applies in full.

## Replay, paper, and demo evidence

- [ ] Replay proves completed-candle alignment and no look-ahead.
- [ ] Backtests disclose conservative fills, cost assumptions, missing depth, and version boundaries.
- [ ] Paper tests cover fill, partial fill, expiry, OCO race, duplicate events, restart, and network uncertainty.
- [ ] Demo token refresh/reconnect and symbol discovery are observed.
- [ ] Paper and cTrader demo use distinct database account identities; a fresh
      demo-only pseudonym and reconciled daily baseline are verified.
- [ ] Demo broker metadata/precision/tick value/volume/margin/order-distance behavior is recorded.
- [ ] Demo OCO peer cancellation, disconnect recovery, and reconciliation are repeatedly supervised.
- [ ] Demo callback/order/deal/position fixtures match supervised broker events;
      the durable journal has no unmatched/conflicting rows and closed-trade
      money-field semantics are approved.
- [ ] Shadow mode runs with a gateway that structurally cannot submit.

## Engineering and operations

- [ ] All quality gates in `plan.md` pass with reviewed artifacts.
- [ ] Database constraints, backups, isolated restore, and migrations are tested.
- [ ] Critical audit persistence, redaction, alerts, heartbeats, and resource monitoring are tested.
- [ ] Dashboard/control API is loopback-only or behind authenticated TLS proxy.
- [ ] Least-privilege users, protected env files, filesystem paths, and service hardening are reviewed.
- [ ] Broker session/spread/slippage/margin/exposure limits are approved for the exact symbol/account.
- [ ] Incident, emergency stop, cancellation, reconciliation, update, rollback, and recovery drills pass.

## Independent live gates

Every startup and order requires all items; no item substitutes for another:

Demo broker order placement is separately disabled by default. It requires
`DEMO_TRADING_ENABLED=true` and the exact acknowledgement
`I_UNDERSTAND_DEMO_ORDERS_USE_A_BROKER_DEMO_ACCOUNT`; neither setting affects live gates.
The initial demo baseline preflight must be performed before enabling those
settings, under `EMERGENCY_STOP=true`, and places no order.

- [ ] `TRADING_MODE=live`.
- [ ] `LIVE_TRADING_ENABLED=true`.
- [ ] `LIVE_TRADING_ACKNOWLEDGEMENT=I_UNDERSTAND_LIVE_ORDERS_CAN_LOSE_MONEY` exactly.
- [ ] Operator manually created `LIVE_ENABLEMENT_FILE` with required instance/account pseudonym, nonce, expiry, and restrictive owner/mode; no project script creates it.
- [ ] Startup safety checks succeeded and match current configuration hashes.
- [ ] Authorized dashboard user created a separate unexpired acknowledgement in `runtime_controls`.
- [ ] Environment, sentinel, and database emergency stops are all inactive.
- [ ] No daily/operational risk lockout exists.
- [ ] Market/candle/depth data are complete, fresh, aligned, and continuous.
- [ ] Reconciliation proves no relevant existing position/pending/partial/unknown/cancellation state.
- [ ] Exact broker symbol metadata and account conversions are valid/current.
- [ ] AI output passes strict size/JSON/schema/semantic validation.
- [ ] Deterministic risk, spread, slippage, volume, exposure, margin, duplicate, and audit checks approve.

## Manual enablement format

The enablement file is deliberately not generated by scripts. Its documented parser requires a JSON object containing `instance_id`, pseudonymous `account_key`, a random one-use `nonce`, `created_at`, `expires_at`, and the exact statement `LIVE ORDERS AUTHORIZED FOR THIS INSTANCE`. It must be owned by the service identity or root, not group/world writable, and expire within the configured review window.

After a process restart, strategy/config/account change, safety-check failure, emergency stop, acknowledgement expiry, or live incident, remove the file and repeat review. Never commit it.
