# Result-derived candidate checks

Issue [#451](https://github.com/AegisFintech/scalping-bot/issues/451), following
the deployed fixed-method experiment loop. This batch supplies the bounded
generation and independent software-validation boundary. Publication and
separately authenticated review remain gates, never a model-declared PASS.

The first approved task is a descriptive recorded-payoff audit. A closed experiment
supplies its full packet, actual close-window rows, independently recomputed
measurement and immutable result/finding identities. Codex may return one standalone
research module. The coordinator creates its provenance note; the model cannot edit
instructions, execution, tests, workflows or the working tree. Existing module/path
collision and exact-base verification remain #448 responsibilities.

The audit counts unknown amounts, flats, wins and losses, sums recorded signed fees
without subtracting them twice, and reports absolute losses divided by the average
winning net. This is a historical descriptive ratio, not a predicted recovery rate,
position-sizing input or strategy qualification. It does not answer arbitrary advisor
questions or imply a positive return. Original questions and all trials stay archived.

Generation has one durable claim per task/base/finding, a four-attempt task budget,
bounded input/output, a distinct tool-disabled Codex thread and response-first crash
recovery. Unknown provider outcomes never redispatch. Generated source remains data.
Only `decimal`, `typing` and future imports are admitted; static restrictions are
dependency hygiene, while the #421 namespace is the execution security boundary.

The immutable sandbox transport receives input cases and returns candidate output.
It receives no expected answers. The trusted parent scores the actual rows plus
empty, unknown, flat and 24 fresh randomized cohorts using separately implemented
Decimal arithmetic. Tests and runtime are pinned independently of candidate code.
Source, bundle, result, finding, challenge, runtime, verifier and output digests bind
the receipt. A durable execution claim prevents restart redispatch. A successful
receipt says `AWAITING_INDEPENDENT_REVIEW` with publishing/broker authority false.
Candidate tests are excluded from normal pytest discovery before any such files
can be published. Original trusted tests continue to run normally.
