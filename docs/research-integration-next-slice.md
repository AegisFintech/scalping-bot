## Concrete blockers found

1. **Plans currently mean frozen training data.** `research_program.py:159–166` rejects `dataset_version` differing from `store.meta('dataset').version`; `plan_input_schema:45` publishes that constant. But `LearningEvidence.dataUse` explicitly means external observations, not a dataset partition. An honest external scope must carry source ID, immutable packet hash and observation cutoff, with legacy plans keeping their current rules. Do not replace the old `dataset` value or consume its protected validation budget.

2. **Unknown costs cannot be represented in plans.** `create_plan:156–158` requires a nonempty finite nonnegative numeric costs object, while the bridge/replay retains unknown counterfactual costs. For the additive observation scope, permit explicit null/not-applicable cost semantics and keep actual decimal strings in diagnostic artifacts. Do not insert zero commission merely to pass registration. Existing `agent_outcomes.record:39–46` permits null metrics/costs but only numeric nonnull values; summarized decimal economic facts therefore need a typed artifact reference, not float conversion.

3. **Custom tools alone cannot restrict the advisor.** `AgentAdvisor.run:478–494` unconditionally adds `experiment_start`, `experiment_retire` and `engineering_deploy`; `execute:432–444` implements those directly. A smaller `AgentTools.catalog()` and `engineering=None` are insufficient: paper experiment actions still exist. Add one central permission check before reservation/side effects, using the same capability set to build the schema. Test direct forged calls as well as model responses.

4. **The old outer loop is coupled to paper and publication.** `ResearchHarness.research_once:234–291` reads/freezes/trains the old OHLC dataset, uses a 100% daily-return aspiration and paper accounting, then `:317–350` publishes tools and evaluates paper candidates; its finally block schedules engineering verification. Do not call this method for the scalper. A small new entrypoint should compose the existing Advisor/Store with external observations and fixed tool capabilities, without invoking this outer loop.

5. **Advisor process access remains a real boundary.** `lab_codex.py:150–152` launches `--yolo`; `child_environment:59–64` retains host `CODEX_HOME`. A restricted Python dispatch catalogue does not contain an advisor able to execute shell commands as root. Run provider reasoning under a dedicated identity/profile, with only its own authentication and bounded sanitized workspace; no broker secrets, SSH roots, raw state backend credentials or mutable project tree. Test filesystem/network/child-process boundaries. #421's candidate worker does not by itself isolate the separate advisor launcher.

6. **Results accept only older tools.** `agent_outcomes.record:18` requires successful `analysis`, `tc02_run` or `action_reconcile`; `research_program.reserve:196` and `AgentAdvisor.execute` provenance/summary conditions name those tools. Update all these together for `scalper_diagnostic`, with a retained artifact hash and exact source/dependency identity. Otherwise the first success cannot become a genuine plan-linked finding.

7. **Capacity/identity need verification before activation.** The last reported agenda had 20 open plans, the exact cap in `create_plan:180`. Reconcile completed/resolved plans through existing APIs; never bulk-close unresolved historical jobs or increase limits to hide stalling. One local packet's changed/active cohort is not a continuous cumulative trade denominator; polling must retain exact windows and avoid double-counting carry-in records.

## What can run safely first

After tests and reviewed delivery: fixed read-only export/import and deterministic diagnostic, under dedicated identities with durable packet/source receipts and bounded retry. It can populate verified observations and a plan result without any model or broker command. Report it as an automated observation pipeline, **not autonomous learning**. Retain existing feed/view services; old engine/agent stay disabled.

Next, enable only the restricted existing advisor to interpret that exact result, record a supported/negative/insufficient finding and close its plan. Start on one archived current-contract packet and one subsequent fresh packet; no new trade is required to prove the information plumbing. Enable periodic work only after restart/duplicate/failure tests and one complete real cycle. Publish cadence, last successful completed cycle, current evidence watermark and exact blocker; a heartbeat is insufficient.

## Minimum tests and acceptance

- Archive reconstruction: correct packet round trip; duplicate/stale revision; tampered/missing records; wrong source/hash; symlink/oversize refusal; no mutation of archive history.
- Additive plan scope: valid external packet accepted; wrong scope/cutoff/hash rejected; legacy dataset mismatch still rejected; frozen dataset/attempt counter/13 unknown jobs unchanged.
- Decimal/null facts survive artifact transport; no float conversion or zero-filled unknown costs.
- Diagnostic positive/open/partial/unsupported/WAIT cases; missing paths stay null; duplicate windows do not add false trades; current policy is not substituted for historical acknowledgement.
- Every forbidden action denied before dispatch, even if directly injected or absent from catalogue; no paper/engineering/protection/control call.
- Crash after reservation, result persistence and finding persistence: retry reconciles exact job/result; no duplicate execution/false finding; unresolved remains unknown.
- One real result→finding→close has server-assigned cycle/source provenance; software smoke success is not counted as economic validation.

Not checked: current remote filesystem permissions, state-backend grants, fresh API capacity or #421 runtime isolation receipt. Risk: the existing advisor is not safe to reactivate merely because candidate tests are sandboxed; its own launcher and built-in capabilities must be restricted too.
